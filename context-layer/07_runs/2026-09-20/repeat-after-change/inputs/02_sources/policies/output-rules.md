# Правила формата результата

## Общий стиль

Пиши кратко, структурированно и деловым языком.

Не используй рекламный тон, общие фразы и необоснованные обещания.

## Базовая структура executive brief

Для управленческого brief используй структуру:

1. Краткое резюме
2. Цель
3. Статус запуска
4. На какие данные опираемся
5. Ключевые сигналы
6. Ключевые риски
7. Открытые вопросы
8. Решения, которые нужны от CEO / команды
9. Следующие шаги

Ключевые обязательные пункты executive brief:

- статус запуска
- ключевые риски
- решения, которые нужны от CEO

## Базовая структура weekly update

Для еженедельного обновления используй структуру:

1. Статус недели
2. Что изменилось с прошлого обновления
3. Главные достижения
4. Три главных риска
5. Блокеры
6. Решения, которые нужны
7. Следующие шаги

## Требования к качеству

Результат считается хорошим, если:

- его можно использовать без полного переписывания;
- из него понятно, что произошло;
- ясно, какие решения требуются;
- видны риски и открытые вопросы;
- нет выдуманных фактов;
- структура повторяема.

## Если данных не хватает

Добавь отдельный блок:

```text
Пробелы в данных:
- ...
```

Не скрывай неопределённость внутри уверенного текста.

## Решения, которые нужны от CEO

Блок должен содержать конкретные, ясные решения, которые только CEO может принять. Каждое решение должно иметь:

- Четкую формулировку вопроса или проблемы
- Варианты решений (если их несколько)
- Последствия каждого варианта
- Срок, к которому нужно решение
- Пользу для бизнеса, если решение будет принято

Примеры:

- “Нужно утверждение на расходы > 100k для масштабирования отдела”
- “Требуется решение: продолжить инвестиции в направление X или остановить проект”
- “Нужно согласовать приоритет между проектом A и проектом B”

Избегай:

- Расплывчатых просьб (“нужна помощь”);
- Решений, которые CEO не может принять;
- Проблем без контекста, почему это критично.

## Запрещённые паттерны

Не писать:

- “это революционное направление” без доказательств;
- “клиенты точно готовы платить”, если в контексте нет подтверждения;
- “риск низкий”, если риск не оценён;
- длинные вступления;
- абстрактные рекомендации без следующего действия.
