# Правила работы с ИИ в ACME Labs

## Назначение

Этот файл задаёт базовые правила работы с ИИ внутри демонстрационной среды ACME Labs.

## Общий принцип

ИИ используется для ускорения работы с контекстом, сценариями и результатами. Он не заменяет владельца решения и не должен скрывать неопределённость.

## Что можно использовать

Можно использовать:

- публичные материалы компании;
- обезличенные заметки клиентов;
- внутренние документы без чувствительных данных;
- шаблоны документов;
- рабочие сценарии;
- результаты предыдущих прогонов;
- явно сформулированные правила и ограничения.

## Что использовать осторожно

Требует осторожности:

- клиентские интервью;
- финансовые данные;
- персональные данные сотрудников;
- закрытые стратегические документы;
- документы под NDA;
- данные, по которым можно восстановить конкретного клиента.

## Что нельзя использовать без проверки

Нельзя без отдельного разрешения:

- реальные имена клиентов;
- персональные данные;
- пароли, ключи доступа, токены;
- закрытые финансовые показатели;
- юридически чувствительные документы;
- конфиденциальные условия контрактов.

## Правило чувствительных данных

Если материал нельзя бездумно отправить коллеге внутри компании, его нельзя автоматически считать пригодным для ИИ-среды.

## Требования к результатам

Любой результат ИИ должен:

- явно опираться на предоставленный контекст;
- не придумывать факты;
- разделять факты, выводы и гипотезы;
- указывать пробелы в данных;
- быть пригодным для проверки человеком.

## При нехватке данных

Если данных недостаточно, ИИ должен:

1. явно указать, каких данных не хватает;
2. не заполнять пробелы выдуманными фактами;
3. предложить вопросы для уточнения;
4. отделить уверенные выводы от гипотез.

# Правила формата результата

## Общий стиль

Пиши кратко, структурированно и деловым языком.

Не используй рекламный тон, общие фразы и необоснованные обещания.

## Базовая структура executive brief

Для управленческого brief используй структуру:

1. Краткое резюме
2. Цель
3. Статус запуска
4. На какие данные опираемся
5. Ключевые сигналы
6. Ключевые риски
7. Открытые вопросы
8. Решения, которые нужны от CEO / команды
9. Следующие шаги

Ключевые обязательные пункты executive brief:

- статус запуска
- ключевые риски
- решения, которые нужны от CEO

## Базовая структура weekly update

Для еженедельного обновления используй структуру:

1. Статус недели
2. Что изменилось с прошлого обновления
3. Главные достижения
4. Три главных риска
5. Блокеры
6. Решения, которые нужны
7. Следующие шаги

## Требования к качеству

Результат считается хорошим, если:

- его можно использовать без полного переписывания;
- из него понятно, что произошло;
- ясно, какие решения требуются;
- видны риски и открытые вопросы;
- нет выдуманных фактов;
- структура повторяема.

## Если данных не хватает

Добавь отдельный блок:

```text
Пробелы в данных:
- ...
```

Не скрывай неопределённость внутри уверенного текста.

## Решения, которые нужны от CEO

Блок должен содержать конкретные, ясные решения, которые только CEO может принять. Каждое решение должно иметь:

- Четкую формулировку вопроса или проблемы
- Варианты решений (если их несколько)
- Последствия каждого варианта
- Срок, к которому нужно решение
- Пользу для бизнеса, если решение будет принято

Примеры:

- “Нужно утверждение на расходы > 100k для масштабирования отдела”
- “Требуется решение: продолжить инвестиции в направление X или остановить проект”
- “Нужно согласовать приоритет между проектом A и проектом B”

Избегай:

- Расплывчатых просьб (“нужна помощь”);
- Решений, которые CEO не может принять;
- Проблем без контекста, почему это критично.

## Запрещённые паттерны

Не писать:

- “это революционное направление” без доказательств;
- “клиенты точно готовы платить”, если в контексте нет подтверждения;
- “риск низкий”, если риск не оценён;
- длинные вступления;
- абстрактные рекомендации без следующего действия.

</document>
