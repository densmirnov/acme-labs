# ACME Labs: демонстрационная ИИ-среда

ACME Labs — вымышленная SaaS-компания и рабочий пример того, как повторяемый бизнес-процесс превращается в воспроизводимый маршрут для человека и ИИ-агента.

Сквозной процесс репозитория — подготовка еженедельного обновления по запуску нового продуктового направления. В примере есть контекст компании, политики, входы конкретного прогона, контракт процесса, результаты двух версий, журнал наблюдений, eval-кейсы и готовый skill.

## Быстрый старт

### Изучить готовый маршрут

1. Прочитайте `AGENTS.md`.
2. Откройте `workflows/weekly-launch-update/README.md`.
3. Сравните результаты `workflows/weekly-launch-update/runs/v0.1/output.md` и `workflows/weekly-launch-update/runs/v0.2/output.md`.
4. Посмотрите в `workflows/weekly-launch-update/run-log.md`, какое наблюдение привело к каждому изменению.

### Повторить процесс

1. Прочитайте `workflows/weekly-launch-update/workflow-contract.md`.
2. Используйте материалы из `workflows/weekly-launch-update/inputs/`.
3. Сохраните новый результат в отдельную папку внутри `workflows/weekly-launch-update/runs/`.
4. Добавьте наблюдение и следующее изменение в `workflows/weekly-launch-update/run-log.md`.

### Собрать свой процесс

Скопируйте `templates/workspace/` и заполните карточку задачи, источники, правила и сценарий. Для зрелого повторяемого процесса используйте шаблоны `templates/workflow-contract.md` и `templates/run-log.md`.

## Структура репозитория

```text
acme-labs/
  AGENTS.md                      общие правила рабочей среды
  context/                       стабильный контекст компании и запуска
    people/                      роли ключевых участников
  policies/                      общие правила и ограничения
  workflows/
    weekly-launch-update/        один полный рабочий маршрут
      inputs/                    данные текущего прогона
      runs/                      результаты и наблюдения по версиям
      examples/                  отдельные сложные случаи
      workflow-contract.md       источник правды о процессе
      run-log.md                 история прогонов и изменений
  skills/                        упакованные повторяемые навыки
  evaluations/                   обычные, рискованные и неполные случаи
  templates/                     заготовки для переноса на свой процесс
  examples/                      дополнительные заполненные примеры
```

## Как разделены уровни

- `AGENTS.md` и `policies/` задают постоянные правила рабочей среды.
- файл `workflow-contract.md` внутри каждого workflow описывает логику одного процесса;
- папка `inputs/` внутри workflow содержит данные конкретного прогона;
- папка `runs/` и файл `run-log.md` внутри workflow сохраняют состояние и историю изменений;
- `skills/` содержит сценарии, которые уже готовы к повторному использованию.
- `evaluations/` проверяет устойчивость на разных типах входов.

## Минимальный запрос

```text
Прочитай AGENTS.md, policies/ и workflows/weekly-launch-update/workflow-contract.md.

Используй входы из workflows/weekly-launch-update/inputs/ и подготовь Weekly Launch Update.

Не придумывай отсутствующие факты. При конфликте источников примени правило из контракта. Если сработала stop condition, остановись и объясни причину.
```

## Главное правило

Не автоматизируйте процесс до того, как появился повторяемый маршрут, проверяемый результат и журнал наблюдений.
