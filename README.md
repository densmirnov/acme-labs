# ACME Labs

ACME Labs — вымышленная SaaS-компания на 25 человек, которая развивает PolicyOS и проверяет новое направление AI Workspace Layer. Это общий учебный репозиторий компании: её контекст, источники, правила, рабочие процессы и примеры работы с ИИ.

На одном наборе материалов можно изучить компанию, подготовить управленческий документ, собрать контекстный слой или проверить повторяемый процесс. Все люди, клиенты и бизнес-события в кейсе вымышлены.

Скачайте [ZIP репозитория](https://github.com/densmirnov/acme-labs/archive/refs/heads/main.zip) и распакуйте его либо выполните `git clone https://github.com/densmirnov/acme-labs.git`. ## Один набор знаний, несколько задач

```text
acme-labs/
  AGENTS.md                    правила работы агента
  context/                     компания, продукт, роли, исходные документы
    README.md                  карта источников и их полномочий
    representations/           представления со ссылками на оригиналы
    decision-rules.md          применение решений к задачам запуска
  policies/                    общие правила ИИ и результатов
  workflows/                   процессы, выбранные входы и история
    weekly-launch-update/
      workflow-contract.md     действующий учебный контракт 0.2
      context-capsule.md       выбранный контекст для одного запуска
      inputs/                  зафиксированный учебный период
      runs/                    отдельные результаты, включая старые примеры
  workshops/                   два учебных маршрута по общей основе
  skills/                      пример упаковки повторяемого процесса
  evaluations/                 проверочные случаи и демонстрационные оценки
  examples/                    образцы результатов, не источники решений
  templates/                   заготовки для собственного процесса
```

Контекстный слой — это связь источников, знаний, правил и способов их применения. Здесь он распределён между `context/`, `policies/` и `workflows/`. Отдельное дерево `context-layer/`, повторявшее эти роли указателями, объединено с основной структурой. [Карта переноса](workshops/README.md) связывает прежние пути и семь папок учебного шаблона с текущими файлами.

Новые задачи используют общие материалы по ссылкам. Копии входов нужны для фиксации конкретного прогона, а не как ещё одна редактируемая база знаний.

## Как читать даты и результаты

Материалы запуска относятся к **18–22 мая 2026 года**. Слово `current` в имени файла обозначает этот учебный цикл, а не сегодняшнюю неделю.

- **15 августа 2026** — контрольная дата проверки направления по [утверждённой цели](workflows/weekly-launch-update/inputs/approved-launch-goal.md).
- **1 августа** — неутверждённое предложение выпустить первую версию из [заметок команды](workflows/weekly-launch-update/inputs/current-week-notes.md).
- **3 июня** — запрос Sales на демо; [решения прошлого цикла](workflows/weekly-launch-update/inputs/previous-decisions.md) требуют проверки границ данных и решения CEO.

Вводная [цель направления](context/launch-goal.md), утверждённая цель цикла и [черновик executive brief](examples/executive-brief-first-run.md) имеют разные роли. Предложения из черновика не становятся решениями компании. В данных нет факта пяти проведённых демо или трёх полученных пилотов: это целевые показатели.

Старые ответы и оценки сохранены как учебные примеры. Они не подтверждают результат вашей модели, реальную экономию времени или готовность к автоматизации. Новая редакция репозитория сама по себе не является новым запуском; результаты собственной практики сохраняйте отдельно.

## Первый запрос агенту

```text
Прочитай AGENTS.md и workflows/weekly-launch-update/context-capsule.md.
Подготовь Weekly Launch Update за указанный в пакете учебный период.
Используй только выбранные источники. Не читай готовые ответы и оценки.
Сохрани новый черновик в новой папке runs/ этого workflow,
зафиксируй входы, условия запуска и наблюдение в журнале.
При обязательной остановке сохрани причину и вопрос человеку.
```

Для сравнения «без контекста / с контекстом» сначала выполните [инструкцию воркшопа](workshops/context-layer/03_use_and_improve.md): запуск в корне репозитория уже получает часть контекста через инструкции среды.

## Как развивать ACME

Обновляйте знание там, где находится его оригинал; у представления сохраняйте источник, статус и период. Для нового процесса добавляйте свой контракт, входы и историю в `workflows/`, используя общие правила компании. Не меняйте прежние источники и ответы ради нового примера. Для нового периода создавайте отдельный набор входов и явно выбирайте его в пакете задачи.

Любой новый результат остаётся черновиком до проверки владельцем процесса. Автоматической внешней отправки в этом примере нет.
