# Workflow Contract: Weekly Launch Update

Версия: 0.1

Статус: историческая версия, использованная для первого прогона.

Владелец: Надя Орлова, Product Lead

Назначение: каждую неделю готовить короткое обновление по запуску нового направления для CEO и команды.

Содержательная логика ранней версии сохранена. Пути к файлам приведены к текущей структуре репозитория.

## Запуск

Каждый понедельник утром перед weekly sync по запуску.

## Входные данные

Минимальный набор:

- цель запуска из `../../context/launch-goal.md`;
- текущие сигналы клиентов из `../../context/customer-notes.md`;
- изменения за последнюю неделю;
- решения, принятые на прошлой неделе;
- текущие риски и блокеры;
- вопросы, которые требуют решения CEO.

Изменения недели, решения и риски собираются вручную из заметок и памяти владельца процесса. Обязательный перечень файлов и порядок приоритета источников не заданы.

## Шаги ИИ

1. Прочитать цель запуска и текущий контекст.
2. Выделить, что изменилось за неделю.
3. Сформулировать статус запуска.
4. Выделить три главных риска.
5. Определить, какие решения нужны от CEO или команды.
6. Сформировать короткий update в заданном формате.
7. Отдельно указать пробелы в данных.

## Формат результата

```text
# Weekly Launch Update

## 1. Краткий статус

## 2. Что изменилось за неделю

## 3. Главные достижения

## 4. Три главных риска

## 5. Блокеры

## 6. Решения, которые нужны

## 7. Следующие шаги

## 8. Пробелы в данных
```

## Критерии качества

Результат считается хорошим, если:

- CEO понимает статус запуска за две–три минуты;
- явно указаны риски;
- понятно, какие решения требуются;
- текст можно отправить после минимальной правки;
- нет выдуманных фактов;
- пробелы в данных названы отдельно.

## Ограничения

- Не превращать update в длинный отчёт.
- Не скрывать риски в середине текста.
- Не придумывать прогресс, которого нет в данных.
- Не использовать имена клиентов.
- Не писать общими фразами вроде «команда активно работает».

## Черновой запрос

```text
Прочитай контекст запуска, правила работы и последние материалы.

Подготовь weekly launch update для CEO.

Соблюдай формат из сценария. Не придумывай факты. Если данных не хватает, явно укажи пробелы.
```

## Результат

`runs/v0.1/output.md`

В этой версии ещё нет явных предусловий, приоритета источников, состояния процесса, шагов человека, quality gate и stop conditions. Эти элементы появились в версии 0.2 после разбора первого прогона.
