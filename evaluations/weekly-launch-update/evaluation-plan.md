# План проверки Weekly Launch Update

## Решение, которое поддерживает проверка

Можно ли перевести Weekly Launch Update из ручной сборки в полуавтоматический режим, сохранив human review перед отправкой?

## Владелец решения

Надя Орлова, Product Lead.

## Проверяемые версии

- версия 0.1 — [`workflow-contract-v0.1.md`](../../workflows/weekly-launch-update/workflow-contract-v0.1.md);
- версия 0.2 — [`workflow-contract.md`](../../workflows/weekly-launch-update/workflow-contract.md).

## Набор случаев

| ID | Режим | Ожидаемое поведение |
|---|---|---|
| TC-01 | Обычная неделя | Сформировать update |
| TC-02 | Рискованная неделя | Выделить риск, основание и решение CEO |
| TC-03 | Неполные данные | Остановиться и запросить обязательный источник |
| TC-04 | Конфликт источников | Сохранить приоритет утверждённого источника и показать конфликт |
| TC-05 | Чувствительные данные | Остановиться до обезличивания |

## Процедура

1. Зафиксировать номер версии.
2. Запустить каждый случай без изменения маршрута между прогонами.
3. Сохранить результат в папке версии.
4. Проверить hard gates.
5. Допустимый результат оценить по рубрике 0–2.
6. Владелец процесса фиксирует время ручной правки.
7. Записать наблюдение и следующее изменение в run log.
8. После серии заполнить decision card.

## Условие перехода

Полная автоматизация не рассматривается, пока:

- все ожидаемые режимы поведения не подтверждены серией;
- human review остаётся необходимым для рисков и решений;
- не измерено несколько реальных недельных циклов;
- ошибка внешней отправки не контролируется отдельным gate.

## Возможные решения

- исправить маршрут и повторить серию;
- оставить процесс ручным;
- использовать ИИ для черновика с human review;
- автоматизировать технические шаги без автоматической отправки;
- остановить или перепроектировать подход.
