# Weekly Launch Update: полный пример рабочего маршрута

Эта папка объединяет входные данные, контракт процесса, правила для агента, критерии проверки, журнал запусков и два примера результата.

## Сквозной процесс

Надя Орлова, Product Lead ACME Labs, каждую пятницу готовит `Weekly Launch Update` для CEO. Задача процесса — за две-три минуты дать руководителю ясный статус запуска, три главных риска и решения, которые требуют его участия.

## Как пройти пример

1. Прочитайте четыре файла в `inputs/`.
2. Откройте `outputs/weekly-update-v0.1.md` и посмотрите, какие проблемы остались в первом результате.
3. Изучите `workflow-contract-v0.2.md`, `agent-instructions.md` и `quality-gates.md`.
4. Сравните результаты в `outputs/weekly-update-v0.1.md` и `outputs/weekly-update-v0.2.md`.
5. Откройте `source-conflict.md`, чтобы увидеть правило обработки противоречащих дат.
6. Посмотрите в `run-log.md`, почему появился каждый элемент версии 0.2.
7. Используйте `skill-package-map.md`, если хотите упаковать процесс как навык.

## Входы для второго прогона

- `inputs/current-week-notes.md` — факты текущей недели;
- `inputs/previous-decisions.md` — решения прошлого цикла;
- `inputs/customer-signals.md` — обезличенные клиентские сигналы;
- `inputs/launch-goal.md` — утверждённая цель и контрольная дата.

## Состав папки

| Файл | Назначение |
|---|---|
| `workflow-contract-v0.2.md` | Полная логика рабочего маршрута |
| `agent-instructions.md` | Общие правила поведения агента в рабочей среде |
| `quality-gates.md` | Критерии качества, проверка перед передачей и условия остановки |
| `source-conflict.md` | Пример конфликта источников и правило его разрешения |
| `run-log.md` | История запусков, наблюдений и изменений |
| `skill-package-map.md` | Структура переиспользуемого skill-пакета |
| `inputs/` | Входные данные текущего цикла |
| `outputs/` | Результаты и их сравнение |
